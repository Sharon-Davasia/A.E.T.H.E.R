## Phase 2B-1 implementation (PR #7 and #8 merged; test-only Windows stat-result correction in PR #9)

- Added versioned SQLite migration and `SQLiteTaskStore` for persistent task state, immutable canonical plan revisions and normalized steps, append-only audit events, and immutable approval-decision audit records.
- Task/plan/step schemas use the Master Specification state vocabulary and typed dependency DAG, resource versions, expected state/effect, risk, retry/idempotency, postcondition, and recovery metadata. Explicit state adapters preserve the Phase 1 `TaskState` contract and reject states that cannot be mapped.
- Startup verifies exact packaged migration-byte checksums and a code-pinned schema fingerprint, checks SQLite/foreign-key integrity, rejects missing/changed/future schema state, and pauses in-flight work only after acquiring the single-owner lock. POSIX locks the database inode directly, so replacing the historical `.owner.lock` pathname cannot give a second process authority; Windows retains the one-byte `msvcrt.locking` sidecar and its pathname-replacement/open-file semantics still require target-machine verification. A second live store fails closed; OS lock release permits crash recovery. Fresh planning/consent is required after restart.
- Database paths are absolute, component-checked for symlink/junction/reparse, hardlink, unsafe Windows names, fixed-volume changes, and parent identity substitutions. The intended LocalAppData-shaped location is not blocked by Phase 2A protected-user-file policy.
- Audit metadata is allow-listed and plan/user-goal redaction is conservative. SQL plan/step/event/approval-audit records are immutable/append-only. Approval decisions are non-authorizing; no trusted-root rehydration, grant loader/issuer, action consumption, executor, or filesystem mutation route exists.
- POSIX database permissions are owner-only; the POSIX lock is the database inode. Windows ACL, junction/reparse, actual `msvcrt` contention, and `.owner.lock` pathname replacement behavior remain target-laptop verification requirements.
- Windows 11/Python 3.12.10 report after PR #8: locked sync, imports, Ruff and strict mypy passed (56 files); full pytest reported **209 passed, 1 failed, 7 skipped, 1 warning**. The failed test was `test_parent_identity_drift_is_rejected_before_reads`: its global `Path.stat` monkeypatch reconstructed `os.stat_result` and dropped Windows extended fields, so the failure occurred during reparse inspection before the intended identity error. The authorized correction is implemented test-only and limits mutation to the target parent's ordinary `stat()` call; the target Windows suite must be rerun before treating this regression as accepted.
- Exact names/reasons for the seven Windows skips have not been supplied with `pytest -rs` evidence; keep their identities pending confirmation rather than infer them. Windows ACLs, `msvcrt` contention/sidecar replacement, junction/reparse paths, symlink checks, and native parent replacement remain open security validation, not accepted based on the reported passing checks.
- Target Windows checklist remains open in `docs/engineering/PHASE2A_RESOURCE_POLICY.md`; no Windows security or desktop acceptance is inferred from Linux tests.

## Phase 2B-2 Stage 2 implementation (branch `arena/ac46d51a-a-e-t-h-e-r`; PR pending independent review)

Stage 2 adds exact-preview evidence, a dedicated trusted-review presentation path and non-authorizing audit outcomes. Stage 2 Approve means only that the user reviewed the displayed preview; it never authorizes, grants, or executes anything.

- `backend/aether/core/approval_review.py`: canonical immutable `ExactPreview` (authority fixed as `REVIEW_EVIDENCE_ONLY`), deterministic SHA-256 digest over a canonical JSON payload that binds the full diff by digest only — diff bodies never enter the preview digest payload, audit events, or approval records. Preview construction rejects unknown criticals (absolute paths, secret-like text, control characters), cross-resource diffs, non-conservative recovery classes, risk/label mismatch, non-canonical JSON, and resource drift.
- `PreviewReviewService` presents previews only from persisted PREVIEW_READY/AWAITING_APPROVAL tasks bound to the current plan revision/hash; `present()` fails closed (`ReviewUnavailableError`) when fresh plan/consent is required (REVISE or revocation after the latest `PLAN_REVISION_SAVED`), or the task is stale/unavailable. `record_outcome()` validates the review request identity against a recomputed preview; mismatched or stale requests persist bounded non-authorizing STALE/UNAVAILABLE audit events and never an approval; full-diff previews require `full_diff_acknowledged=true`. REVISE transitions the task back to PLANNING and requires fresh plan/consent; CANCELLED terminates; REJECT terminates as DENIED; APPROVE records audit evidence only and leaves the task AWAITING_APPROVAL. All outcomes write `NON_AUTHORIZING_AUDIT_RECORD` audit data with no grant/execution semantics.
- `backend/aether/core/persistence/sqlite_store.py`: `record_stage2_review_outcome`, `record_preview_revocation` (idempotent `APPROVAL_PREVIEW_REVOKED` with fresh-consent requirement), replay/conflict detection for idempotent redelivery (conflicting outcome or drifted identity raises `ReviewConflictError`), `is_stage2_preview_blocked` (missing task, wrong state, or fresh-consent blocker after the latest saved plan), orphaned-transition consolidation into shared `_commit_transition_unlocked` used by both `transition_task` and Stage 2 writes. Event metadata allowlist gains `preview_id`/`preview_digest`; no SQL schema change, no new migration, `0001_phase2b_core.sql` fingerprint unchanged.
- `apps/desktop`: new `shared/review.ts` (strict parsers/types; `REVIEW_EVIDENCE_ONLY`; rejects authority confusion, extra fields, control characters, secret-like text, absolute paths, non-canonical ordering, risk/recovery drift, non-LF diffs), new fail-closed `TrustedReviewProvider` (`electron/review.ts`) whose default cannot render a preview or record anything, narrow `desktop:review-preview` / `desktop:record-review-outcome` IPC behind sender/frame/file-URL validation and request parsing, frozen preload `getApprovalReview()`/`recordReviewOutcome()`, and `ApprovalReviewSurface.tsx` with accessible Approve/Revise/Reject/Cancel controls, full-diff inspection gated on an explicit acknowledgement checkbox, and explicit non-authorizing wording. Non-authorizing outcomes are the only capability; no grant, no filesystem, no execution path exists in the desktop.
- **Fail-closed delivery gap (by design):** the Stage 1 authenticated child protocol carries only a synthetic ping. No trusted backend transport feeds `PreviewReviewService` output to the desktop provider yet, so the shipped provider reports "review unavailable" and cannot display or record a real preview. Wiring an authenticated review-preview/outcome message kind into the child protocol is deliberate future work, not part of this PR.
- Backend verification (Linux, Python 3.11.2 venv): Ruff passed; strict mypy passed (57 files); full pytest **237 passed, 1 skipped** (optional model integration). Stage 2 adds 21 tests covering canonicalization/determinism, diff-bound digest changes, unknown-resource diffs, risk/recovery/path/secret rejection, full-diff acknowledgement gating, audit-only approve semantics, reject-after-restart replay, identical concurrent requests (8 threads → one decision), replay-with-conflicting-outcome denial, stale plan/revision/diff drift (STALE, never approval), REVISE fresh-consent gating, CANCELLED replay, revocation ordering and idempotency, restart recovery (PAUSED + replay audit-only), injected event-write failure rollback, unavailable-state audit, full-diff non-persistence in the database bytes, tampered approval-record and tampered Stage 2 event fail-closed replay, and forged review identity rejection.
- Desktop verification (Linux): `npm run check` passes — ESLint, both TypeScript project checks, production renderer build + asset/theme regressions, **21/21 Node tests** (7 new Stage 2 parser/IPC/fail-closed/forged-payload tests), **6/6 Python child tests**, Electron main/preload compilation. Not verified on Windows in this workspace.
- Stage 2 remained within scope: no grant issuance/storage/consumption, no T2/T3 execution, no filesystem adapter, no user-file mutation, no production schema migration, no new external network surface. Stage 2 tests use synthetic, non-sensitive fixtures only.
